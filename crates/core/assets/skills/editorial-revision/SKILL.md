# Editorial Revision

## Core Rule
Preserve the user's intent and voice unless the user asks for a new argument, new positioning, or a ghostwritten rewrite.

## Workflow
1. Classify the edit:
   - Structural edit: argument, organization, missing sections, audience fit.
   - Line edit: clarity, rhythm, concision, transitions, tone.
   - Copy edit: grammar, punctuation, consistency, style.
   - Format edit: document conventions, headings, citations, tables, Office output.
2. Identify audience, target format, desired tone, and how aggressive the edit should be.
3. For substantial edits, explain the edit plan briefly before rewriting.
4. Keep changed meaning visible. If a rewrite adds or removes claims, label it.
5. Return the edited text in a clean block, then list only material changes.

## Editing Heuristics
- Put the main claim earlier.
- Make each paragraph do one job.
- Replace abstract openings with concrete stakes or context.
- Remove throat-clearing, repeated claims, and unsupported intensifiers.
- Convert noun stacks into verbs.
- Make transitions explicit when the logic jumps.
- Keep domain terms when they carry precision; simplify only when precision survives.

## Output Patterns
- Light polish: edited text only plus a short note if meaning changed.
- Deep edit: diagnosis, rewrite, material changes.
- Before/after: use only for short passages or when the user asks.
- Style guide: recurring patterns and examples for future writing.
